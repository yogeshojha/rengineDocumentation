Besides the web pages, this site publishes a Markdown copy of every page, an index and a full-text file for agents, and the agent files. Point your agent at the one that fits the job:

| Output | URL | Content |
|---|---|---|
| Markdown copy | The page URL with `.md` in place of the trailing slash | One page as Markdown |
| Index | <https://rengine.wiki/llms.txt> | Every page in the navigation, grouped by section, with its description |
| Full text | <https://rengine.wiki/llms-full.txt> | The Markdown copy of the home page and every page in the navigation, in navigation order |
| Agent files | <https://rengine.wiki/agent-files/AGENTS.md>, <https://rengine.wiki/agent-files/CLAUDE.md>, <https://rengine.wiki/agent-files/skills/rengine/SKILL.md> | The [agent files](files/agents-md.md) as plain Markdown |

## Markdown copy of a page

To give your agent one page, use the page URL with `.md` in place of the trailing slash:

| Page | Page URL | Markdown copy |
|---|---|---|
| A page | <https://rengine.wiki/pentesters/install/> | <https://rengine.wiki/pentesters/install.md> |
| A section page | <https://rengine.wiki/agents/> | <https://rengine.wiki/agents.md> |
| The home page | <https://rengine.wiki/> | <https://rengine.wiki/index.md> |

Each copy opens with a header built from the page's front matter, so your agent knows what the page covers, which release it applies to and which source files back it:

```markdown
# Install reNgine

> Install reNgine on a Linux host with one command. The installer checks the host, sizes reNgine for its memory and starts it, then prints the address and the account you sign in with.

Applies to reNgine 3.0.0. Sources: `install.sh`, `README.md`, `docker-compose.prod.yml`, `deploy/rengine`. Revised 2026-10-03.
```

The header lines come from these fields:

| Header line | Source |
|---|---|
| `# <title>` | `title` |
| `> <description>` | `description`, omitted when empty |
| `Applies to reNgine <version>.` | The reNgine release the site documents |
| `Sources:` | `sources`, as repository paths |
| `Generated by` | `generated`, on generated reference pages only |
| `Revised` | `revised` |

The home page copy also lists the audiences and the featured capabilities with links to their Markdown copies, and the install command.

## Copy a page from your browser

When you work with a chat assistant, you can copy a page straight from the site and paste it into the chat. Two controls sit beside the breadcrumb above the title:

| Control | Action |
|---|---|
| **Copy page** | Copies the page's Markdown copy to the clipboard. The label reads **Copied** on success and **Copy failed** otherwise. |
| **View as Markdown** | Opens the page's Markdown copy. |

## The index: llms.txt

Give your agent `/llms.txt` when it should find the right page on its own. It lists every page with its description, grouped by section, and links to the Markdown copies. `/llms.txt` starts with the site name, the site description as a block quote, and a line naming the Markdown URL form and `/llms-full.txt`. One `##` heading follows per navigation group. A group is named after the top-level section and its first subsection, joined by a colon: `## Pentesters: Start`, `## Agents: MCP server`. Each entry is one line:

```markdown
## Agents: Agent files

- [AGENTS.md](https://rengine.wiki/agents/files/agents-md.md): Give your coding agent the layout, commands, checks and rules of the reNgine repository in one file, so it follows the project's conventions and runs the same checks as CI. Save it at the root of your reNgine checkout.
```

A page without a description is listed by title alone. The home page comes first, under `## Home`.

## The full text: llms-full.txt

Give your agent `/llms-full.txt` when it should have every page at once, for example to load the docs into a project. `/llms-full.txt` starts with the same lines as `/llms.txt`. The home page and then every page in the navigation follow in navigation order, each preceded by a `---` rule and an HTML comment holding the URL of its Markdown copy:

```markdown
---

<!-- https://rengine.wiki/pentesters/install.md -->

# Install reNgine
```

## How a page becomes Markdown

The Markdown copy keeps the content of a page and drops its layout. The site builds it from the page source after the reference counts are filled in. This table shows what happens to each part:

| In the page source | In the Markdown copy |
|---|---|
| `{{ counts.<key> }}` tokens | The computed number |
| Layout wrappers: `div.rn-split`, `div.rn-prose`, `div.rn-pane` | Removed. The prose, then the pane content, in source order. |
| The pane head | A bold line with the view name and its scope |
| A tab (`/// tab`) | A bold line with the tab label, then the tab content |
| A pane label or note | An italic line |
| An interface recreation, `div.rn-ui` | `*Interface: <description>*`, from its `aria-label` |
| A callout, `note`, `warning` or `danger` | A block quote. The first line is the callout title in bold, or the callout kind when the title is empty. |
| A "Shown in the pane" reference | Removed |
| Keys | A code span. `++ctrl+k++` becomes `Ctrl+K`, `<kbd>K</kbd>` becomes `K`. |
| Inline HTML: `span`, `b`, `small`, `em` and similar | Removed. The text is kept. |
| Attribute lists such as `{ .rn-q }` | Removed |
| A link to another page | The absolute URL of that page's Markdown copy, with its anchor |
| A code block | Unchanged |

Consecutive blank lines collapse to one.

## Fetch the files

Any HTTP client can fetch them:

```bash
curl -s https://rengine.wiki/llms.txt
curl -s https://rengine.wiki/agents/mcp/connect.md
curl -s https://rengine.wiki/llms-full.txt -o rengine-docs.md
```

If your coding agent works on the reNgine code, give it [AGENTS.md](files/agents-md.md). If your agent should work with your reNgine instance, connect it to the MCP server: see [Connect your agent](mcp/connect.md).
