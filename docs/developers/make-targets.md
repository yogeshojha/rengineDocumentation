The `Makefile` at the repository root saves you from typing long `docker compose` commands. Run `make` with no target to print the list under `reNgine 3.0 Dev Commands`. Every Docker target acts on `docker-compose.yml`, the development stack.

## Docker

Use these to start, stop and rebuild the stack, and to follow its logs.

| Target | Command | Use |
|---|---|---|
| `make up` | `docker compose up -d` | Start all services |
| `make down` | `docker compose down` | Stop all services |
| `make build` | `docker compose build` | Rebuild all containers |
| `make logs` | `docker compose logs -f` | Tail all logs |
| `make logs-api` | `docker compose logs -f api` | Tail the api logs |
| `make logs-worker` | `docker compose logs -f worker-default worker-scans worker-control` | Tail the three worker logs |

## Checks

Run these before you open a pull request. They run the same commands CI runs.

| Target | Command | Use |
|---|---|---|
| `make lint` | `$(RUFF) check $(PACKAGES)`, `$(RUFF) format --check $(PACKAGES)`, then `cd frontend && npm run lint` | ruff, prettier and ESLint |
| `make test` | `docker compose exec -T api /app/.venv/bin/python -m pytest tests -q`, then `cd frontend && npm run check && npm run test` | pytest in the running api container, then svelte-check and vitest on the host |

See [Tests and CI](tests-and-ci.md) for what CI checks. You can change two variables on the command line:

| Variable | Value | Override |
|---|---|---|
| `RUFF` | `uvx ruff@0.14.14` | `make lint RUFF=ruff` uses a ruff already on the `PATH` |
| `PACKAGES` | `api shared reports worker stages tools toolbox interest mcp channels connectors tests scripts` | |

`uvx` needs uv on the host. The frontend commands need `npm ci` in `frontend/` on the host.

## Database migrations

Use these when you change a table. reNgine's migrations are hand-written, so `migrate-create` gives you an empty revision to fill in, and `migrate-draft` gives you an autogenerated draft to cut down.

| Target | Command | Use |
|---|---|---|
| `make migrate` | `docker compose exec api uv run alembic upgrade head` | Apply all pending migrations |
| `make migrate-create m="<message>"` | `docker compose exec api uv run alembic revision -m "<message>"` | An empty revision to hand-write |
| `make migrate-draft m="<message>"` | `docker compose exec api uv run alembic revision --autogenerate -m "<message>"` | An autogenerated draft to edit down |
| `make migrate-history` | `docker compose exec api uv run alembic history --verbose` | Show the migration history |
| `make migrate-downgrade` | `docker compose exec api uv run alembic downgrade -1` | Roll back the last migration |
| `make db-reset` | `alembic downgrade base`, then `alembic upgrade head`, in the api container | Drop every table and apply the migrations again |

If you leave out `m`, `migrate-create` and `migrate-draft` print `Usage: make migrate-create m='migration message'` or `Usage: make migrate-draft m='migration message'` and exit with status 1.

`db-reset` prints `Every table is dropped and the migrations are re-applied.` and asks `Continue? [y/N]`. It continues only when you type `y`.

!!! danger "db-reset"
    `make db-reset` drops every table of the development database, with every target, scan and setting in it.

The migrations run in the api container, which mounts `alembic/` and `alembic.ini`. Restart the api after `make migrate`.

## Shells

Use these to look inside a running container or the development database.

| Target | Command | Use |
|---|---|---|
| `make shell-api` | `docker compose exec api bash` | Shell in the api container |
| `make shell-worker` | `docker compose exec worker-default bash` | Shell in the `worker-default` container |
| `make db-shell` | `docker compose exec db sh -c 'psql -U "${POSTGRES_USER:-rengine}" -d "${POSTGRES_DB:-rengine}"'` | `psql` on the development database |
